## 1. Design

The rule as the owner settled it on 3 November 2026: under 1000 changed lines of hand-written
files, added plus removed, `git diff --numstat -M` from the merge base to the head.

- **What counts**: source (`.java`, `.scala`, `.py`, `.sh`, `.yml`, `.yaml`, `.xml`, `.sql`,
  `.properties`), plans and other hand-written text, and hand-curated data (`.md`, `.txt`,
  `.tsv`), `census_curated.txt` included by the owner's word. A pure rename and a binary file
  count nothing.
- **What does not**: a generated file, which is one the attributes mark as `git check-attr` reads
  them (`merge=varka-generated` in `sql/varka/.gitattributes`, or `linguist-generated` there and in
  `dev/.gitattributes`, which name the timing TSVs, the ledger, the census and demo outputs and the
  canary files), or one whose first lines say a tool wrote it ("Generated by", "Generated, not
  written", Spark's "Automatically generated by", "DO NOT EDIT": the first 40 lines of source, the
  first 5 of text, past which the phrase is a plan's prose), which catches the emit cost tables, the
  reports, the protobuf stubs and two Spark suites' markdown, but not a SQL test input under
  `sql-tests/inputs/`, which is hand-written though one carries that header; results files, the text
  under `results/` and `benchmarks/` directories (a `.md` there included) and Spark's plan stability
  goldens, while source there counts; the transcribed papers under `sql/varka/papers/`; and the
  `READING_*.md` notes.
- **Whose rules**: a file the base has is judged by the base's path, attributes and text, so a
  pull request cannot exempt its own edit by adding a header or an attributes line or moving
  the file into `results/`; the check counts it and prints "exemption added by this pull
  request". A file new in the head is judged by the head's, and one only attributes the pull
  request adds exempt is printed too. Below git 2.40 the attributes are read by hand from the
  two files above. Whether a file diffs as binary is read from the base's attributes alone
  (`git --attr-source`, git 2.42's; older git cannot count), never the head's, the user's or the
  system's, and a base text file the head gives a NUL counts as text. An octopus merge in a
  sync, which `--remerge-diff` cannot replay, is a count not made.
- **Generated blocks**: `docs/sql-varka.md` and `SKILLS.md` count their prose only. The blocks
  their writers name (`VarkaCoverageSuite`'s three, `dev/varka_toc.py`'s contents) are dropped
  from both sides, a BEGIN only with its own END, and the rest is diffed by `git diff --no-index`.
  A named BEGIN or END without its partner counts the whole file; any other marker is prose. The
  driver's self-test checks the names against every tracked marker and the attributes reading
  against `git check-attr`.
- **Where it runs**: `pr` counts HEAD, or `--number`'s head (fetched if missing; a head it cannot
  find is a finding), against `--base`, by default `VARKA_DIFF_BASE` or the merge base with
  `origin/master`; `size` counts alone, with `--head X` read under X's attributes. The `lint` job
  runs `size` first, against `VARKA_DIFF_BASE`, and fails when that is empty.
- **Syncs**: a branch named `varka-sync-apache-*` whose range merges a commit of Apache Spark's
  master (`refs/apache/master`, which the step fetches for such a branch, or a remote of
  `apache/spark`) counts only its own commits, each against its parent, and each merge by its own
  changes, `git show --remerge-diff` (the conflict resolutions and any edit made in the merge),
  under the same exemptions, each file cut to the lines that differ from both parents (row 588:
  `git show --cc`'s `++` and `--` lines, so a conflict kept whole on one side counts nothing).
  The name without such a merge is counted as any branch.
- The `lint` job's size step continues on error and the job's last step fails the job when it
  failed (row 588), so the other lint steps still run on a change over the cap.
- At 1000 or more counted lines the check fails, naming the count, the total and the five
  largest counted files; below, it prints counted against total.

## 2. Done when

- both scripts' self-tests cover the cases above, each file's count checked on one fixture with
  its own attributes;
- the `lint` job fails a pull request at or over the cap;
- this row's own pull request is under it.
