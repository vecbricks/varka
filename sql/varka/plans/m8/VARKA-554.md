# VARKA-554: Every pull request under 1000 changed lines

*Written 3 November 2026 from the owner's rule of that day: a Varka pull request stays under
1000 changed lines of hand-written source and docs. Built the same day on `varka-554-pr-size`.*

## 0. What exists now (admission check)

From master at `8363562c827`.

1. Nothing measures a pull request's size. `dev/varka_msg_check.py pr` checks the title and body
   before `gh pr create`; the Build's `varka-docs` job checks them again, but that job runs only
   when a document or a house-rule tool changed (`dev/sparktestsupport/modules.py`,
   `varka_docs`), so a change of Java alone never reaches it. The `lint` job runs on every change
   and has the merge base in `VARKA_DIFF_BASE`.
2. The generated files are known in two places. `sql/varka/.gitattributes` names the seven the
   merge driver merges, and `dev/varka_precommit.sh --install-hook` adds the docs file;
   `dev/varka_regen_generated.sh --all` kept a second, shorter list of its own.
3. `docs/sql-varka.md` is mostly prose: its three generated blocks are 675 of its 2191 lines.
4. Six markdown reports are generated, each opening with "Generated by": the coverage reports
   under `sql/varka/coverage/` and the two mutation reports. Results files live under
   `results/` directories.
5. Two open branches, measured by the check against `8363562c827`: `varka-343-casts` counts 2483
   of 3274 changed lines, `varka-348-conditions` 2134 of 6340.

## 1. Design

- **What counts**: `git diff --numstat -M` from the merge base to the head, added plus removed,
  for `.java`, `.scala`, `.py`, `.sh`, `.yml` and `.md` files. A pure rename counts nothing, a
  binary file nothing. Other extensions (`.txt`, `.sql`, `.xml`, `.properties`) fall outside the
  rule as written, `census_curated.txt` included.
- **What does not**: a file on the merge driver's list, read through its `generated_files()`
  (`--list`), which `--all` now reads too, so the lists cannot drift; anything under a
  `results/` directory; a markdown file whose first five lines hold a "Generated by" line. The
  JSON, TSV and SMT-LIB files are outside the extensions already.
- **The docs file** counts its prose only: the generator owns a third of it, so it is not
  excluded whole; both sides drop their generated blocks (the driver's `hand_lines`) and the
  remainders are diffed.
- **Where it runs**: `pr` counts HEAD (or `--number`'s head, when in the clone) against
  `--base`, by default `VARKA_DIFF_BASE` or the merge base with `origin/master`; `size` counts
  alone, and the `lint` job runs it first, against `VARKA_DIFF_BASE`, with no JVM. A branch
  named `varka-sync-apache-*` is not counted: its merge-base diff is Apache Spark's work.
- At 1000 or more counted lines the check fails, naming the count, the total and the five
  largest counted files; below, it prints counted against total.

## 2. Done when

- `dev/varka_msg_check.py --selftest` covers a count under the cap, one at it, the docs file's
  blocks, a generated report, a results file, a rename and a sync branch;
- the `lint` job fails a pull request at or over the cap;
- this row's own pull request is under it.

## 3. Open points for the lead

1. Sync branches are exempted by name; a sync pushed under another name is counted and fails.
2. Should `.txt` and `.sql` count? A hand-curated list such as `census_curated.txt` (52 lines
   on `varka-348-conditions`) does not today.
