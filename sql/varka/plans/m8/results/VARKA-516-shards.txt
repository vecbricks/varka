# Where a Varka-scoped Build's wall time goes, shard by shard (VARKA-516), 30 October 2026: six
# Varka-scoped Builds of MaxGekk/spark, read-only. Job and step times from the Actions API, each
# Varka job's phases from its log's timestamps, its CPU from the "Record the CPU and the vector
# width" step's line, each suite's and test's seconds from the job's varka-scoped-junit-* artifact.
# Nothing was rerun or dispatched. The replays of section 6 run dev/varka_suite_shards.py's own
# placement over the measured seconds; nothing was run on the laptop.
#
# Commands:
#   gh run list -R MaxGekk/spark -w Build -L 40
#   gh api "repos/MaxGekk/spark/actions/runs/<run>/jobs?per_page=100"
#   gh api repos/MaxGekk/spark/actions/jobs/<job>                       # a job's steps
#   gh api --allow-escape-sequences repos/MaxGekk/spark/actions/jobs/<job>/logs
#   gh run download <run> -R MaxGekk/spark -p 'varka-scoped-junit-*'
#
# A job's phases, from its log: setup is the job's start to the suites step's "== job" line
# (checkout, caches, Java, the compile state's download and unpack); build is "== build:" to the
# first "== 0 configuration(s)" line (sbt compiling what differs from the restored state); tests
# is that line to the run's "defaults" report line, the module's suites over two JVMs at a time;
# quiet+uploads runs to the new tests' step (the JIT-measuring suites alone, catalyst's platform
# smoke, sql's first job's compile-state save and the artifact uploads); new-tests+post is the
# rest (the change's new tests rerun five times, the fix check, post steps). A Build's wall is its
# first job's start to its last job's end.

## 7. What else sits on the path

The precondition ("Check changes", ubuntu-slim) runs alone before every other job: 1.9 to 2.9
minutes in the six Builds, most of it the full-history checkout, 137 s in 41105632364 and 98 s in
41089478930. Each Varka job's checkout takes about a minute more of its setup.

The Linters job ("Linters, licenses, and dependencies") starts after the base image, about 4.5
minutes in, and ends 12.3 to 15.2 minutes after the Build's first job in the five Builds without
long new tests (section 1); its Scala linter step took 227 s in 41105632364 and 174 s in
41089478930. It is the Build's next longest job once the Varka jobs end sooner.

41099294241 is left out of the baseline: its catalyst 3 of 3 spent 1698 s in "The new tests of
catalyst, rerun five times" (its log: "fails-on-base: not a pull request labelled fix"), the
change's own new tests in the job its suite fell to, which no split of the suites moves. Its
suites step and phases are kept in the tables above.

The option matrix's classes job ("Varka option matrix classes") ended 6.6, 6.7, 6.5, 6.0, 7.2
and 5.8 minutes after the first job, in the order of section 1, before any Varka suites job.

A rerun: Build 40947407586 (varka-524-session-configs) has two attempts. Its second re-ran only
the jobs the first failed: sql 1 of 3, whose JUnit upload had failed with "Failed to CreateArtifact:
Unable to make request: ECONNRESET", and catalyst 3 of 3. catalyst 2 of 3 kept its first attempt's
start, 20:17:35Z, and the run holds one varka-scoped-junit-catalyst-2of3 artifact. So no job there
uploaded a JUnit artifact twice under one name.
