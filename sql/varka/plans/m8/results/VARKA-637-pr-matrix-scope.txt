## Source

2026 00:00 UTC to the reading, from the Actions API (runs, then each run's jobs with
filter=latest). 62 dispatches; 3 have no jobs listed (the jobs API returned none) and one is the
master run 44485292430, so 58 are pull request branches (one, 45029680160, was cancelled
after its build job). Three were still running at the reading,
so their bin-minutes are partial.

Columns: bins, the bin jobs listed; bin-min, the summed minutes of the bin jobs that ran (start
to completion, cancelled and skipped jobs left out); longest, the longest such bin in minutes;
wall, the run's first job creation to its last job completion in minutes; wait, the median bin
job's minutes from creation to start, which is the queue for the fork's 40 slots. The jobs API's
filter=latest gives each job's latest attempt, so a run whose bins were re-run carries the re-run
attempt's times against the first attempt's creation: 44882879917 (356-trig) was re-run
(run_started_at 08:48 against created_at 08:01 UTC), its median wait came out negative, and it is
shown as n/a; its bin-min is the re-run attempt's. The master run 44485292430, left out of the
totals, read 193 jobs, 191 bins, 1,457 bin-min, longest 19.6, wall 60, wait 18.2; it ran without
a reach record.

## Tier of each run's diff

The diff is the head against its merge base with vecbricks/varka's master as it stood when the
run was created (the last first-parent master commit before created_at). The tiers are a
first-match draft of the rules VARKA-637.md 3.1 designs:

  suites   only test suites (*Suite.scala or *Suite.java under sql/catalyst or sql/core src/test),
           with documents, tooling or benchmarks beside them
  none     documents: *.md, sql/varka/plans, skills, papers, figures, the benchmark results and
           provenance files, workflows other than the option matrix's
  tooling  dev/ scripts other than the matrix's own
  matrix   the matrix's own: dev/varka_matrix*, varka-option-matrix.yml, sql/varka/matrix/*.tsv
           but skips.tsv
  all      anything else: main code, test classes that are not suites, generated data files,
           unknown paths

A run takes the widest tier any of its paths has. The draft is coarser than VARKA-637.md 3.1 as
reviewed: it puts docs/sql-varka.md under none, which VarkaCoverageSuite reads, so the
353-support-table-r run (tooling here) would be a suites run of VarkaCoverageSuite under 3.1; no
other run of the 8 narrower ones touches a file a suite reads, and the totals stand.
