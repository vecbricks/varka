Inputs, for each run of MaxGekk/spark:
  gh run download RUN -R MaxGekk/spark -D DIR    (every bin artifact, the reach, the report)
  gh api 'repos/MaxGekk/spark/actions/runs/RUN/jobs?per_page=100&filter=all' --paginate \
      --jq '.jobs[]' > jobs-RUN.jsonl
  the suites as the run's build listed them, at the run's head (dev/varka_matrix.sh --list-suites
  --module M, which reads the sources only; without --defaults, as CI lists them)

Step 1, the artifacts: 43642146943 has 155 bin jobs and 155 bin artifacts, 44485292430 has 190
and 190; every bin job has its artifact with each unit's seconds and JUnit reports. The 156 and
191 of results/VARKA-570-bin-times.txt count the job "Option matrix: build and plan" as a bin.
Every unit of every bin is read back: the planner at the run's head, given the run's
configurations, suites and reach record, cuts 43642146943's 155 bins with the same units in the
same order (73197 s planned, as its build job's summary line says), and 44485292430's 190.

The model. A bin job is its measured set-up and upload around its units, which run in the order
the job started them on two lanes, each started as a lane frees. Jobs start in bin order on the
run's slots (the most bin jobs it ran at once), each after the run's median wait for a runner
once a slot is free. "jobs as run" times the run's own jobs at their measured lengths, the slot
model alone; "as run" times them from their units, the bin model too; "replanned" times the
bins the planner cuts now, each unit its suites' measured JUnit seconds plus the run's median JVM
overhead, each bin the run's median set-up and upload.

      [--reach DIR/varka-option-matrix-reach/reach.tsv] --plan-from HEAD_OF_RUN \
      [--pairs DIR/varka-option-matrix-report/config-suite-seconds.tsv \
       --suite-seconds DIR/varka-option-matrix-report/suite-seconds.tsv]
