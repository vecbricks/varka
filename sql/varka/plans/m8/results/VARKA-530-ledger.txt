The report job (not changed here: .github/workflows/* is changed by other open pull requests).
One step after "Summary" in varka-option-matrix.yml's report job puts this run's lines in its
summary and warns on each failed or flaked test, and on each test of the committed ledger with
at least 3 flakes in 14 days; the bins are complete when the report job runs, and `run` reads
a run in progress:

    - name: The CI ledger's lines of this run
      if: always()
      env:
        GH_TOKEN: ${{ github.token }}
      run: |
        python3 dev/varka_ci_ledger.py run "$GITHUB_RUN_ID" --annotate --flaky-threshold 3 \
          | tee -a "$GITHUB_STEP_SUMMARY" || true

(The warning commands then show in the summary as text too, which is harmless.)

It needs `actions: read`, which the job's default token has. The post-merge routine runs
`dev/varka_ci_ledger.py update` and commits ledger.tsv. The self-test runs nowhere in CI until
`python3 dev/varka_ci_ledger.py --self-test` joins the docs job's "The house rules' checks pass
their own cases" step, beside the other CI tools' self-tests.

The skip list's citations (not added). Every reader of sql/varka/matrix/skips.tsv requires
exactly five fields: VarkaMatrixRuns.parseSkips throws on any other count,
dev/varka_matrix_report.py's skip_lines raises ValueError on a sixth field (checked with a
six-field line), and dev/varka_lint.py's skips-tsv rule reports it. So no column was added.
Proposed: a sixth column, `ledger`, holding the lines that justify the entry as
`<run>/<attempt>` keys joined by commas (a line is then found by run, attempt, configuration,
suite and test, which the entry already names), or `-` for an entry older than the ledger; the
three readers accept five or six fields, and the lint checks that each cited run has a ledger
line for the entry's (configuration, suite, test). A `fails` entry never reaches the ledger
again once it is listed, since the matrix then expects it to fail, so its citation is the run
that showed the failure before the entry was added.
