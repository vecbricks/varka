# Varka Task 3 - `VarkaClassLoader` + per-task class lifecycle

**Status: PLAN SAVED - implementation not started.** See
`PLAN_MILESTONE_1.md` for the high-level MVP plan. The Spark-side
`TaskCompletionListener` wiring and the integrated Metaspace stress loop are
follow-ups to the Spark-side integration (Tasks 4-7); Task 3 delivers the
standalone Java loader plus unloadability proof.

## 1. Goal

A dedicated, per-task class loader for generated bytecode so that classes can
be unloaded when the task ends (Metaspace safety under high query diversity).
Pure Java in the standalone engine module. Exposes an explicit `release()`
protocol; unloadability is proven deterministically with weak references.
Registry + `findClass` mirror Spark's `InMemoryClassLoader`.

## 2. Investigated areas (findings)

### 2.1 Spark's existing pattern (grounding)

`CodeCompiler.scala` shows what Spark does today and `VarkaClassLoader` should
mirror it:

- `JdkCodeCompiler` uses a private `InMemoryClassLoader extends
  ClassLoader(parent)` that overrides `findClass` ->
  `defineClass(name, bytes, 0, bytes.length)` (CodeCompiler.scala:1656-1665).
- Instantiation is always `loader.loadClass(GeneratedClassName)
  .getConstructor().newInstance()` (CodeCompiler.scala:1353-1359).
- **Key Metaspace risk today:** `CodeGenerator.compile` caches the
  `(loader, code)` result (CodeGenerator.scala:1567), so the loader stays
  referenced and classes are never unloaded under high query diversity.
  Varka's differentiator is a per-task loader with no global retention. The
  Ghost-fallback cache (Task 5) will cache only *Janino* classes by plan hash
  - an accepted retention for the fallback path only.

### 2.2 What makes a class unloadable

- A class unloads when its defining loader becomes unreachable and no live
  references to the `Class`/instances remain; the JVM then collects it and
  frees Metaspace.
- `defineClass` alone does not make the loader retain the class - the
  reference is one-way (`Class` -> loader).
- Therefore `release()` must clear any class registry the loader keeps, and
  the owner (Spark task) must drop its references to the generated
  `Class`/instance. Both are required for unloading.

### 2.3 Class registry design

- A `ConcurrentHashMap<String, Class<?>>` registry backed by a `findClass`
  override enables `loadClass`, matching Spark's pattern. `release()` clears
  it, breaking loader -> class retention so the loader becomes collectable.
- `defineClass` is `protected final` and synchronized; concurrent
  define/load is safe without `registerAsParallelCapable` (not needed - the
  loader is per-task and effectively single-threaded by design).
- `defineClass` throws `SecurityException` for `java.*` packages - not
  applicable to our generated packages.

### 2.4 `TaskContext` lifecycle hook (verified)

- `TaskContext.addTaskCompletionListener(f: TaskContext => U)` exists
  (TaskContext.scala:141) and runs on success, failure, and cancellation.
- The binding is a one-liner: `ctx.addTaskCompletionListener(_ =>
  loader.release())`. It requires Spark core (Scala, Java 17), so it is
  deferred to the Spark-side integration (Tasks 4-6). The standalone engine
  module is Java 25 with no Spark dependencies.

### 2.5 Class-File API for generating test classes (verified on JDK 25)

`java.lang.classfile` is final and needs no module flags. Confirmed surface:

- `ClassFile.of().build(ClassDesc, Consumer<ClassBuilder>)` -> `byte[]`.
- `ClassBuilder.withMethodBody(String, MethodTypeDesc, int flags,
  Consumer<CodeBuilder>)`, `withSuperclass(ClassDesc)`,
  `withFlags(AccessFlag...)`.
- `CodeBuilder`: `aload`, `invokespecial(ClassDesc, "<init>", MethodTypeDesc)`,
  `invokestatic`, `loadConstant(String)`, `return_`, `areturn`, `lreturn`.
- Test classes are generated on the fly (no fixture `.class` files); one
  method uses `invokestatic(System.currentTimeMillis)` to exercise parent
  delegation.

### 2.6 Metaspace verification without flakiness

A "Metaspace plateau" assertion is flaky. The deterministic guarantee is
weak-reference based: after `release()` + dropping references + retried
`System.gc()`, the loader's `WeakReference` must be enqueued, which proves the
loader (and its classes) were collected. As a diagnostic, log
`MemoryPoolMXBean` used for the "Metaspace" and "Compressed Class Space" pools
before/after (never asserted).

### 2.7 Placement decision

Java in the standalone engine module (`org.apache.spark.sql.varka.execution`).
This deviates from VISION's "Scala" for this file, which is a Catalyst-side
concern; the loader core is pure JDK. It builds/tests immediately with the
existing JUnit 25 setup and avoids forcing the unresolved "Spark-side home"
decision before it is needed.

## 4. API and semantics

```java
package org.apache.spark.sql.varka.execution;

public final class VarkaClassLoader extends ClassLoader {
  public VarkaClassLoader(ClassLoader parent);

  // Defines a generated class; returns it. Throws IllegalStateException if released.
  public Class<?> defineGeneratedClass(String className, byte[] bytes);

  // Idempotent, thread-safe. Clears the class registry so the loader becomes collectable.
  public void release();

  public boolean isReleased();

  @Override protected Class<?> findClass(String name);  // backed by the registry
}
```

Semantics:

- `defineGeneratedClass` -> `defineClass(className, bytes, 0, bytes.length)`,
  registers in a `ConcurrentHashMap<String, Class<?>>` (enables `loadClass`),
  returns the `Class`. `IllegalStateException` after `release()`.
- `findClass` -> registry lookup, else `ClassNotFoundException` (mirrors
  Spark's `InMemoryClassLoader`).
- `release()` -> `volatile boolean released = true`; registry cleared.
  Documented contract: the owner must also drop its references to the
  generated class/instance; only then does the loader become unreachable and
  its classes unload from Metaspace.
- No global registry, no caching - the per-task scope is what prevents
  Metaspace bloat.

## 5. Test class generation (Class-File API)

A test helper builds a minimal public class,
`org.apache.spark.sql.varka.gen.GenNNN`:

- constructor: `aload 0; invokespecial(Object.<init>); return_`
- `String hello()` -> `loadConstant("hello"); areturn`
- `long now()` -> `invokestatic(System.currentTimeMillis); lreturn` (parent
  delegation)

## 6. `VarkaClassLoaderTest` - test matrix

1. **Define + instantiate**: define a generated class,
   `loadClass(...).getConstructor().newInstance()`, invoke `hello()`/`now()`,
   assert results; assert `findClass`/`loadClass` works; assert
   `isReleased() == false` before release.
2. **Unloadability (the Metaspace guarantee)**: `WeakReference(loader, queue)`;
   `release()`; drop loader/Class/instance references; retry `System.gc()`
   until enqueued (with timeout); assert collected.
3. **Batch stress**: 1000 loaders, each defining a unique class
   (`Gen0..Gen999`), all released, all references dropped; assert all weak
   refs are enqueued. Log Metaspace + Compressed Class Space used
   before/after (diagnostic only).
4. **Release lifecycle**: double `release()` OK; `isReleased()` after; define
   after release -> `IllegalStateException`.
5. **Registry semantics**: two classes in one loader both `loadClass`-able;
   `findClass` for an unknown name -> `ClassNotFoundException`.
